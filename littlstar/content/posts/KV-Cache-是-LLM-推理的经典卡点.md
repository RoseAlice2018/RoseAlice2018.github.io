## 1. 为什么要有 KV Cache？（空间换时间）

- LLM 的推理生成文本的方式是“Auto-regressive（自回归）”，也就是根据前文，每次只蹦出一个 Token，并把这个 Token 加入到前文中，再去预测 next token。
- 在 Transformer 核心组件中，Attention 计算公式大概是：
  $Attention = \text{Softmax}(Q \times K^T) \times V$

假设我们已经生成了“我喜欢大”，现在要生成下一个词“模型”。

- **如果不存在 KV Cache（极度浪费计算力）：**
  - 为了生成“模型”，模型需要重新计算“我喜欢大”四个字的 KV。随着句子越来越长，比如生成第 10000 个字，就需要重新计算前面 9999 个词。这会导致计算复杂度呈平方级爆炸，极其缓慢。
- **如果存 KV Cache（典型的空间换时间）：**
  - 前面的 KV 算过一次后，直接存下来，那么生成新 Token 的时候，只需要计算新 Token 的 KV 即可。

**结论：** 存储 KV Cache 是为了避免对历史数据的重复计算，把每一次生成的计算复杂度从 $O(N^2)$ 强行降到 $O(N)$。

## 2. KV Cache 能吃掉多少显存？（Cache 的卡点）

**单个 Token 的 KV Cache 容量** = 2（因为 K、V 两个矩阵） × 模型层数（Layers） × 注意力头的数量（Heads，每个 head 有自己的 KV） × 每个头的维度（Head_dim） × 数据类型字节数（比如 FP16 是两个字节）

我们以一个早期的模型 GPT-3（175B）为例，12288 隐藏维度，96 层：
- 一个 Token KV Cache = 2 × 96 × 12288 × 2 bytes = 4.7 MB
- 假设一个 2048 Token 的上下文：4.7 MB × 2048 = 9.6 GB

以上为一个用户，在一个 2048 Token、Batch Size=1 的情况下，单个显存占用就是 9.6 GB。
可以说吃显存太多了。

## 3. 内存墙

即便我们很有钱，买下超多显卡，有足够的显存存储 KV Cache，性能依然会被卡住。这涉及到一个核心概念：**算子访存比（Arithmetic Intensity）**。

在推理阶段，GPU 的工作流如下：为了生成一个 Token，GPU 需要把历史上所有的 KV Cache 从 HBM 读取到 SRAM 中，在 SRAM 中进行计算。

性能卡点就在于**搬运**。从 HBM 读取到 SRAM，SRAM 的计算很快，但是显存带宽客观限制了搬运速度。类似于 CPU 和内存，CPU 计算很快，但需要等待内存搬运数据。
这就是性能卡点的根本原因：

1. **Memory Wall（内存墙）**：GPU 的显存带宽被瞬间榨干，但计算核心却有 95% 的时间在闲置等待数据。
2. **Batch Size 限制**：破局的办法本来是增加 Batch Size，但是显存容量又限制了 Batch Size 并发计算。

## 解决 KV Cache 问题的探索

### MQA 机制

**1. MQA 的底层原理**
- 标准 MHA 中，$H$ 个 Head 对应 $H$ 个不同的 $W_q, W_k, W_v$ 矩阵。
- MQA 节省 KV，所有 $H$ 个 head 对应 $H$ 个不同的 $W_q$ query，但是只有一个 $W_k$ 和 $W_v$。这意味着，不管有多少个注意力头，映射出来的 K 只有一个向量，V 也只有一个向量。这样就相当于缩小了 $H$ 倍的 KV Cache。

**2. MQA 的问题**
1. **信息瓶颈**：很自然，语言模型中 Q 代表我想要寻找的上下文，K 代表特征，V 代表实际内容。MQA 让 $H$ 个 head（比如 32 个 Q）去匹配同一个 K，K 必须压缩和包含所有历史词汇的复杂特征，这一定会丢失非常多的细节。在长对话或多轮对话，或在细节问题上无法记住这么多特征，会出现问题，导致回答出错。
2. **训练不稳定**：KV 的参数大量减少，在 pretrain 阶段梯度更新集中在 $W_k$ 和 $W_v$，有时会导致训练过程不如 MHA 稳定。
3. **效果衰减**：通俗来说就是“降智”。

### MQA 优化 -> GQA

既然 MQA 的信息太少，MHA 的 KV Cache 太多，折中一下不就好了吗？GQA 就是这样的妥协产物，在 MHA“太费显存”和 MQA“太降智”之间，寻找完美折中点。

**1. GQA 的底层原理**
- 把 $H$ 个 heads 分为 $N$ 个 Group。比如 32 个 heads 分成 8 组，每一组 4 个 Query，但是共用一个 $W_k, W_v$。这样实际显存变成了 $32 / 8 = 4$，即原来的 1/4，但是性能能做到接近。

**2. GQA 的优点**
- **极其平滑的性能曲线**：KV Heads 从 1（MQA）提升到 8（GQA），内存带宽压力并没有增加多少，但是模型的表达能力有了很大提升。
- **可以“平滑升级”**：模型不需要从头训练。如果你手里已经有了一个训练好的 MHA 模型（比如早期的 LLaMA-1），你可以直接通过“平均池化”的方式，把 32 个 KV 头的权重压缩成 8 个，然后用仅仅原始训练量 5% 的数据微调一下，它就能变成一个 GQA 模型。

**补充内容：GQA 的平滑升级**

- **第一步：物理层面的“合并”（Mean Pooling）**
  假设我们手里有一个已经训练好的大模型（MHA 架构），它有 32 个 Q 头，32 个 K 头，32 个 V 头。我们现在想把它变成 8 个 K/V 头的 GQA 模型。
  操作对象是模型的权重矩阵（Weights），也就是 $W_k$ 和 $W_v$。

  **分组（Grouping）：**
  我们把原有的 32 个 K 头按顺序切分成 8 组。
  - 第 1 组：包含第 1、2、3、4 号 K 头。
  - 第 2 组：包含第 5、6、7、8 号 K 头。
  - ……以此类推。

  **平均池化（Mean Pooling / 求均值）：**
  针对第 1 组的 4 个 K 头的权重矩阵，我们直接把这 4 个矩阵加起来，除以 4，求一个平均值。
  新的 $K_1$ 权重 = $\frac{K_1 + K_2 + K_3 + K_4}{4}$
  对 V 头也做一模一样的求均值操作。

  **组装新模型：**
  经过这样暴力的“求平均”后，原本 32 个 K 头的参数，就浓缩成了 8 个 K 头的参数。我们就得到了一个物理结构上完全符合 GQA 要求的模型。

- **第二步：为什么这种“暴力求平均”不会把模型搞傻？**
  你可能会问：直接把 4 个头的参数强行揉成 1 个，模型学到的知识不会乱套吗？
  这里涉及到大模型的一个重要特性：**注意力头的冗余性（Redundancy）**。
  在标准的 MHA 模型中，研究人员早就发现，很多注意力头学到的东西是高度相似、甚至重复的。也就是说，相邻的几个 K 头和 V 头，它们关注的特征往往大同小异。
  这就好比公司里有 4 个秘书（4 个 K 头），虽然各干各的，但他们整理的资料其实差不多。现在公司把他们裁了，换成 1 个“超级秘书”（平均后的 K 头），这个超级秘书吸收了这 4 个人笔记的“核心共性”（均值），他依然能大致覆盖原来 4 个人的工作范围。

- **第三步：为什么还需要 5% 的微调（Fine-tuning）？**
  虽然求平均保留了核心特征，但如果你马上让这个拼装好的 GQA 模型去输出，它的性能是会下降的，表现得就像有点“懵”。
  因为那 32 个 Q 头（高管）还是原来的脾气，他们习惯了以前那种精细的对应关系，现在突然让他们 4 个人去跟 1 个“超级秘书”对接，他们一时半会儿适应不了。
  这时候，5% 的微调就登场了：
  - 我们不需要让模型重新学习“什么是英语”、“什么是逻辑”（这些知识在庞大的前馈神经网络 FFN 里完好无损）。
  - 我们只需要用少量的预训练数据（大约是原训练数据量的 5%），让模型重新磨合一下。
  - 在这 5% 的训练中，Q 头会迅速调整自己的参数，学会如何在这个新的 8 个 K/V 头的环境里，准确地提取信息。

**3. GQA 的问题**
既然是折中，就意味着它在两个极端的指标上都不是绝对的第一：
- **论极限表达能力**：它依然比不上原汁原味的 MHA。在某些极端复杂的逻辑推理或极其精细的上下文对应任务中，MHA 32 个独立 KV 头的表现依然是天花板。
- **论极限推理速度和极低显存**：它依然比不上 MQA。对于那些部署在端侧（比如手机、IoT设备）的超小模型，显存极其吃紧，MQA 依然是最佳选择（比如 Google 的 Gemma 2B 版本就用了 MQA，而 7B 才用 GQA）。

### DeepSeek - MLA 机制

MLA 机制核心思想是：MHA 的性能我想要，但是 KV Cache 我连 GQA 的成本也不想付。

**1. 核心思想：KV Cache 变成 KV Zip（低秩联合压缩）**

**MLA 实现思路：**
- 处理 Token 时，不再直接生成 K、V 矩阵，而是通过一个线性映射，把输入信息狠狠压缩成一个维度很小的“隐向量”，可以理解为一个 Zip。在推理时，显存里只存这个小的 zip。
- 那推理时，计算 attention 时，需要解压缩这个 zip 吗？如果解压缩不还是占用大量显存吗？MLA 妙在这一点，它利用了线性代数里的结合律：
  $(A \times B) \times C = A \times (B \times C)$
- 本来是 `Query × (解压矩阵 × Zip)`，现在变成了 `(Query × 解压矩阵) × Zip`。也就是说，Query 跟解压矩阵提前相乘，就无需解压缩 zip，但是结果一样。

*（注：MLA 会额外保留一个极小的向量专门存储位置信息，但整体极小）*

**2. MLA 对比 GQA**
- **性能上**：MLA 接近 MHA，上限比 GQA 高。
- **显存占用**：小于 GQA。

**3. 为什么没有全换成 MLA？**
- 训练难度高
- 算子需要重写
